As I see it, there are two main types of organization, which each have their own sub categories of course. This first of the two is the one which I described in [[The theory of information]], [[sortational organization]]. This is the act of progressively grouping items into smaller and smaller categories in an arborescent structure. The second of the two is [[relational organization]], which also involves the creation of an arborescent structure. The difference is that the items contained in each point on the arborescence are determined by by their connection/relation to the notes in contained in a given point. 

Sortational organization can still query based on connections, but it can't find anything not contained in the subset (the point); similarly, relational organization still operates on the given subset of the point, but it can find any item in the whole set. 

| Type of organization | Which items it sees (for the query)         | What it does                                    |
| -------------------- | ------------------------------------------- | ----------------------------------------------- |
| Sortational          | The subset of U contained in the current GP | Uses the query to create a new GP (subset of U) |
| Relational           | All the items                               | Uses the query to create a new GP (subset of U) |

As we can see from the table, the only difference between the two methods of organization is the subset of U which they have access to for the queries. Sortational organization is always narrowing down a given set of information, while relational organization is always giving context for the items in question by listing new items in a new list. Often times, a [[relational query]] will be used to give a list of items which have a specific connection to a given note. This will only be one of the KCs leaving the KG. One can continue by redoing said query for all of the other KUs in the KG in the same way. This would lead to a structure which very much resembles that of a relational database. In fact, sortational and organizational queries are what allow us to create KGs which resemble relational databases. Both types of query are essential parts of the same overarching system. 

The act of repeated relational queries in order to achieve uniformly structured information is something that I talked about in The Theory of Information. I proposed that one of the characteristics of organization its *uniformity*, and my recent thoughts seem to confirm my hunch. If we create one rule and apply it to all of the KUs in a given set, we are creating [[uniform organization]]. However, if we make multiple different rules for the KUs, we are partaking in [[irregular organization]].
