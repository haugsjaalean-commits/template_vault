I don't know if it's a good idea to have a clear separation between classes and components. There are arguments for and against the idea. What I have to remember is that there really isn't a *right* answer. The right answer is the system that proves to be the most useful. I cannot 100% predict that, but I can reason and make guesses. 

The arguments *for* revolve around the idea that it adds more flexibility. For instance, I could have a file that inherits from `Art` while still being able to use `Art` as a component in `Goal`. In the end, the fact of the matter is that there is no difference between inheriting through `is a` and `has a`. Both simply give the child all of the parent's characteristics. For this reason, it would make sense to allow both to exist at once. 

The argument against this is that it makes no logical sense at all. No matter how hard I try, it never makes any ontological or semantic sense to have a component which can be instantiated. Simply put, it is one of the strangest things imaginable to me.  

I think that the best idea for my `Goal` class is to get rid of `goal type`. This component field would force anything I ever want to be a goal into ALWAYS being a goal. If I want `Art` to ever be a goal, then it has to inherit from `Goal Type`, and it could no longer be instantiated. The only way to make `Art` would be to make a `Goal`. The only other choice would be to open up the possibility for components to also be instantiated, but, as I said, this really doesn't make any sense at all. Once `goal type` is gone, all goal objects will simply be paired with another `is a` statement for things like art or programming. The nice thing about this is that it doesn't even really add any new steps from the current approach. 

The only other option would be to have certain classes that I know will always be goals simply inherit from `Goal`. That way, I save the step of needing to always specify two `is a` statements. In reality, this wouldn't even really save me any time, because, 99% of the time, the goals I create are sub goals. This means that I would have to prespecify an `is a` for this anyways. No time saved:(
