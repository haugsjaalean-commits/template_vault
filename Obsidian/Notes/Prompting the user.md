In [[Necessary fields]], I walk about how I think it would be cool to have some properties be necessary to an object. This is a good idea, but if the field is not filled in, then it is simply created as an unsolvable discrepancy. This slows down the whole workflow, as the thing telling us what is wrong is in an entirely different place from where we are doing the creating (and it probably won't even be visible). The better option would be to constantly prompt the user about what is happening in the Class Manager. Any discrepancies should show up as little orange tooltips in the active file which can even sometimes give the user options. For example, if a file has a non-accepted characteristic, then they will be directly prompted by a message next to it asking them if they want it to be deleted. There should be something indicating whether or not the discrepancy is solvable. This ties into [[Automatically dealing with unsolvable discrepancies]]. The user should have more options for dealing with discrepancies.
