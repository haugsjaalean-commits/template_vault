I want to give myself the most basic possible definition of organization that will contain all possible variations that I have found. All types of organization come back to the root form of organization. I need to find the most simple possible thing that can be considered *organization*. 

## My attempt at defining organization


I had previously thought that it was possible to create any structure of organization by using the Theory of Multi-level Organization. This seems to be true when it comes to purely [[sortational organization]], but it falls apart when we consider the existence of [[relational organization]]. [[Multi-level organization]] could be used to attain less strict (looser) types of organization, but it cannot make relational organization. It can be used to allow the existence of one KU in multiple places at once in the KG, but it couldn't allow a given KP to contain KUs not in the KP's parent. In reality, this depends on one's interpretation of multi-level organization, as I think it has not yet been well defined. In any case, I do not think that multi-level organization is the answer to the question of the definition of organization. However, the question of whether or not to consider multi-level organization may not even matter in the enod. If multi-level organization makes the creation of any rearrangement of information possible, then this becomes the definition of organization. <[[Thoughts on multi-level organization]]> If multi-level organization cannot create any rearrangement of organization, then I would give the following definition for organization: 

> [!info] Definition of organization
> Organization is the act of creating an arborescence starting at the point O. Each point is a subset of U (the set of all items) containing one or more items. Any point may contain any item and my also contain any number of items. 

Given this definition of organization, one might wonder why I even define it at all if it leaves the door open to seemingly completely useless arrangements of information. The answer to this question is quite simple: to me, organization is simply the set of rules which apply when it comes to arranging information, but the real question is how organized the arrangement is. Some arrangements will be completely useless, while others will show a great deal of utility. This is why I have defined other, more specific types of organization. One of the ways that we can make the organization more organized is by applying the rules of rigid, semi-rigid, and loose organization. Another way is to use relational queries to create relation-database-like organizational structures.
