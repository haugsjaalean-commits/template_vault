In the class basses menu, there will be three dropdowns. One of them will be for `isA()` connections, another for `hasA()` connections, and the last for `typeOf()` connections. They will all have the option to be toggled on. They can all be on at once (the query will be an `or` and not an `and`). (There should be an option in the settings to make it so that only one can be on at a time.) Under each of these dropdowns, there is the option to exclude certain classes from the query. If one class is excluded, then all of its children are turned off as well (because this is how it works anyways). There will obviously be quick options to accept all or exclude all. 

This will allow a more dynamic usage of bases in Obsidian. Combined with [[Dynamic Views]], bases will have almost limitless potential. This feature needs to be implemented in the [[Class Manager]] for the Class Bases feature. 

N.B. Currently, the `exact matches only` option in class bases changes things on a per-view basis. I think that this per-view behavior should stay, so I would suggest moving all of these options into the options for the individual views. These options will still *belong* to Class Bases, but they will live in the native view panel instead of the dedicated Class Bases panel.
